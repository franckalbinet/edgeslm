Coffee water stress

  • Show All Code
  • Hide All Code
Synthetic triage records for the first task: water stress and equipment faults on coffee farms

In the field, the triage comes from code in the domain project: feature engineering and an ML model flag the nodes to watch or fix for one farm and one day. The SLM turns that triage into a WhatsApp message for the farmer, as the scope describes. This module generates synthetic triage records, so that we can build and evaluate the message side before the real triage exists. It generates them in code, without a language model, so every record is valid and a seed reproduces it.

Dimensions

The task has three dimensions with three levels each. A tuple sets the main item of a record: the kind of problem, its spatial pattern and its severity. For both, the record holds at least one item of each kind.

Exported source 
DIMS = dict(problem=['water stress', 'equipment fault', 'both'],
            pattern=['one node', 'cluster', 'widespread'],
            severity=['early', 'moderate', 'severe'])
SEVERITIES = DIMS['severity']
test_eq(len(tuples(DIMS)), 27)

Farm layout

A farm is a list of groups of nodes, each group sharing an irrigation line. The names follow one of three schemes, drawn at random: greenhouse benches (small farms, 4 to 16 nodes), blocks with drip lines, or numbered plots (12 to 80 nodes). Location names are what the farmer reads, so they never contain node IDs.

Causes and onset

Each item reports what the data shows about its cause, never a part that no sensor watches. For water stress, soil_water says whether water still reaches the soil: arriving, or none with the time since the soil last got water, which is never later than the start of the stress. Water that stops arriving is the commoner case, about 70% of items. For equipment faults, fault says what the data shows. Moderate and severe faults are always missing data, by the scope’s definition of fault severity. An early fault on a single node can also be implausible values from one sensor, or a camera whose view has changed; on several nodes at once, an early fault is missing data, since one shared cause is far likelier than many sensors failing in the same way.

Exported source 
FAULTS = ['missing data', 'implausible values', 'camera view changed']
SENSORS = ['soil moisture', 'thermal camera', 'air temperature', 'humidity']

Severity also sets how long ago the problem started. ONSET gives the range of days for each kind and severity. For faults it follows the scope’s definition: no readings for 1 to 3 days is moderate, and more than 3 days is severe.

The record gives the start as a phrase that the message can use as it is, so that neither the teacher nor the SLM has to work out weekdays from dates: since today, since yesterday, since a weekday within the past week, or for a week or more.

Exported source 
ONSET = {('water stress', 'early'): (0, 1), ('water stress', 'moderate'): (2, 4), ('water stress', 'severe'): (4, 8),
         ('equipment fault', 'early'): (0, 1), ('equipment fault', 'moderate'): (1, 3), ('equipment fault', 'severe'): (4, 10)}

Items

One item is one problem at one location. A one node item names a node, a cluster item names a group, and a widespread item covers the whole farm with more than 70% of its nodes flagged. used holds the locations already taken in the record, so that two items never point at the same group.

Messages give no counts, so a cluster or widespread item carries an amount word for the share of its group’s nodes that are flagged: all, almost all (80% or more), most (more than half) or some (half or fewer). The triage computes it, so that neither the teacher nor the SLM does arithmetic:

Triage records

triage is the generator for sample. It builds the main item from the tuple, then adds random variation: the farm and its layout, a day in the Brazilian dry season (May to September), and up to two extra items. Extra items are never more severe than the main one, and are single nodes or clusters. Together, the single nodes and clusters of one kind stay below the widespread threshold: on a small farm, two clusters that flag almost every node would really be one widespread problem, such as a gateway fault. For both, the first extra item is of the other kind. Items are sorted most severe first, so that the message can keep their order. A node that sends no readings cannot be flagged for water stress, so when a both tuple is widespread and moderate or severe, its widespread item is the water stress and the fault is the extra item. The record holds no weather: in the field, weather is an input to the ML model, and its effect shows in severity and in soil_water.

A test set

The test set has 10 records per tuple, 270 in total:

recs = sample(DIMS, triage, 270, seed=1)
test_eq(set(Counter(tuple(r['tuple'].values()) for r in recs).values()), {10})

Every record keeps the rules above. The main item matches its tuple, no item is more severe than the tuple, items are sorted most severe first, every location appears once, both records hold both kinds, no water stress item sits beside a widespread fault that loses data, and the single nodes and clusters of one kind never add up to a widespread item. Each item carries the cause fields of its kind, and nothing else about its cause:

items = lambda r: r['input']['items']
sev = SEVERITIES.index
for r in recs:
    t, main = r['tuple'], items(r)[0]
    test_eq((main['pattern'], main['severity']), (t['pattern'], t['severity']))
    assert all(sev(it['severity']) <= sev(t['severity']) for it in items(r))
    test_eq(len({it['location'] for it in items(r)}), len(items(r)))
    if t['problem'] == 'both': test_eq({it['problem'] for it in items(r)}, set(KINDS))
    ps = {(it['problem'], it['pattern'], it['severity'] != 'early') for it in items(r)}
    if ('equipment fault', 'widespread', True) in ps: assert all(p != 'water stress' for p, *_ in ps)
    assert all(_flagged(items(r), k) < _wide(r['input']['nodes']) for k in KINDS)
    test_eq([sev(it['severity']) for it in items(r)], sorted((sev(it['severity']) for it in items(r)), reverse=True))
    for it in items(r):
        want = {'soil_water'} if it['problem'] == 'water stress' else {'fault', 'sensor'} if it.get('fault') == 'implausible values' else {'fault'}
        test_eq(set(it) & {'soil_water', 'fault', 'sensor', 'likely_cause'}, want)
        if 'nodes_flagged' in it: test_eq(it.get('amount'), amount(it['nodes_flagged'], it['nodes_in_group']))

Records have one to three items, and farms range from a few nodes to about 80:
