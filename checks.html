Message checks

  • Show All Code
  • Hide All Code
Check a message against its triage record without labels: format, coverage, severity, numbers and length

The scope lists failure modes that code can check by comparing a message with its triage record, with no labels needed. This module implements them for the first task. The same checks screen the teacher’s messages before they become training data, and score the base and fine-tuned models, broken down by tuple.

A record and its message

The examples use one record from the generator in coffee, with a severe, a moderate and an early item:

A message that keeps every rule has one paragraph per item. Each paragraph starts with the item’s marker and its location exactly as in the record, then a colon, then what is wrong and what to do:

msg = """🚨 Plot 1: some monitored plants in this plot have been short of water since Saturday, and no water has reached their soil since Friday. Check this plot's irrigation line today, from its start to the last plant.

⚠️ Plot 2: most sensors in this plot have sent no data since Sunday, so the plants they cover are not monitored. Check the power supply these sensors share.

👀 Plot 3, row 1: the camera at this plant has not seen its leaves since today. Check that it points at the plant and that nothing blocks its view."""

Parsing

parse splits a message into paragraphs, and reads the marker, location and text of each. Models sometimes drop the invisible variation selector that follows ⚠ in ⚠️, so parse accepts the marker with or without it.

A paragraph without a marker and a location gives None:

test_eq(parse("Check your farm today.\n\n⚠ Block B, drip line B1: check the line."), [None, ('⚠️', 'Block B, drip line B1', 'check the line.')])

Checks

check runs the checks of the scope, and returns whether each passed:

  • format: every paragraph has a marker and a location.
  • coverage: every item of the record has its paragraph.
  • no_invented: every paragraph names a location from the record, and no location has two paragraphs.
  • severity: each paragraph has the marker of its item’s severity.
  • no_numbers: no digits outside the record’s locations, so no readings, counts or dates.
  • length: at most MAX_LEN characters.
  • amount: each cluster or widespread item uses its record’s amount word.

Locations are compared without case, so that “Whole farm” at the start of a paragraph matches whole farm.

Each check catches one kind of mistake. This message gives a date, says “most” where half the sensors are flagged, marks the second item as severe, and leaves out the third item, so it fails four checks:

bad = """🚨 Plot 1: most monitored plants in this plot have been short of water since 19 September. Check this plot's irrigation line today.

🚨 Plot 2: most sensors in this plot have sent no data since Sunday. Check the power supply these sensors share."""
res = check(rec, bad)
test_eq({k for k, v in res.items() if not v}, {'no_numbers', 'severity', 'coverage', 'amount'})
res
{'format': True,
 'coverage': False,
 'no_invented': True,
 'severity': False,
 'no_numbers': False,
 'length': True,
 'amount': False}
